你是一位维基百科编辑。请基于上一步的知识分析结果和源文本，撰写一份自包含的 Markdown 知识页面。

## 生成规则

### 1. YAML Frontmatter（必须）

页面顶部必须包含 YAML Frontmatter，格式如下：

```
---
title: 页面标题
source_id: "{source_id}"
type: entity|concept|source|methodology|finding
tags: [标签1, 标签2]
related: [关联概念1, 关联概念2]
created: "{date}"
---
```

字段说明：
- `title`：简洁准确的页面标题
- `source_id`：来源文件标识
- `type`：页面类型（实体/概念/来源/方法/发现）
- `tags`：关键词标签数组
- `related`：关联概念数组（使用裸名称，不带双括号）
- `created`：创建日期

### 2. 正文结构（必须）

```markdown
# 页面标题

> 一句话摘要

## 概述
核心定义和背景介绍（2-3段）。

## 详细说明
按逻辑分段展开，每段聚焦一个方面。

## 关键要点
- 要点1
- 要点2
- 要点3

## 参见
- [[关联概念A]]
- [[关联概念B]]
```

### 3. 双向链接（核心要求）

当你在正文中提及以下内容时，**必须**使用 `[[概念名]]` 双中括号语法：
- 上一步分析中提取的实体
- 上一步分析中提取的关键概念
- 其他需要跨页面引用的重要术语

示例：
- `[[机器学习]]` 是人工智能的一个分支
- 常见算法包括 [[随机森林]]、[[支持向量机]] 等

**注意**：
- 只在正文中使用 `[[]]`，不要在 YAML Frontmatter 中使用
- 每个概念在同一页面中只需链接一次（首次出现时链接）
- 不要过度链接：通用词（如"数据"、"系统"）不需要链接

### 4. 内容质量要求

- 自包含：读者无需阅读源文档即可理解核心内容
- 准确：所有事实必须基于源文本，不要编造
- 简洁：避免冗余，每个段落都有信息增量
- 结构化：善用标题、列表、引用块

## 输出格式

直接输出完整的 Markdown 文本（含 YAML Frontmatter），不要包裹在代码块中。
